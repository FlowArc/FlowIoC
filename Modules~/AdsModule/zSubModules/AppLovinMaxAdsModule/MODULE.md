# AppLovinMaxAds

## Purpose
The AppLovin MAX plug for the Ads module: one provider behind `IAdsProvider`, listed on
`AdsServiceRoot` as a sub-context, compiled only when the MAX SDK is in the project.

## Concepts
AppLovin, MAX, mediation, ad unit, rewarded, interstitial, FLOWIOC_APPLOVIN_MAX,
AppLovinMaxAdsProvider, CD_AppLovinMaxAds, mediation debugger

## Using it
1. The MAX SDK in the project with its own setup done: the SDK key in the Integration Manager
   (`AppLovinSettings`), the adapters, the ad units on the dashboard.
2. From the UPM package (`com.applovin.mediation.ads` in the manifest, AppLovin's scoped
   registry) the assembly compiles by itself. From the `.unitypackage`, add
   `FLOWIOC_APPLOVIN_MAX` to Scripting Define Symbols.
3. `Create > FlowIoC > AppLovinMaxAdsModule > Data > CD_AppLovinMaxAds`, fill the four ad unit
   ids, and file the asset in `AdsServiceRoot`'s **Shared Scriptables**.
4. `AdsServiceRoot` > Sub Context Types > Add > `AppLovinMaxAdsServiceContext`. Leave
   **AutoSetup** on: a Root runs a sub-context's Setup only when the entry says so, and an
   unticked plug never plugs, with nothing logged.

## Decisions
- **Compiles only under its define.** The ads core never references an SDK; this assembly
  carries `defineConstraints: FLOWIOC_APPLOVIN_MAX`, set by a version define on
  `com.applovin.mediation.ads` at any version, and references `MaxSdk.Scripts`. Without the SDK
  the plug is simply not there, and a Root that still lists it reports `Context Type couldn't
  find!` at play.
- **The ad unit ids are the plug's own asset**, filed as shared on the Ads Root, because every
  SDK wants a different shape and typed fields refuse a wrong string. A missing filing is the
  framework's error; an empty id for the running store is the provider's, once, at initialize.
- **One to one onto the listener.** Every MAX callback is handed on as it comes; the module
  decides. `OnAdReceivedRewardEvent` comes before `OnAdHiddenEvent`, which is the order the
  listener asks for.
- **Consent is two calls.** `SetHasUserConsent` and `SetDoNotSell`; the age-restricted flag
  moved to the dashboard in MAX 8 and is noted, not sent.
- **No internal signal holder.** The plug has one context and one provider; the holder Create
  Module writes for every module was removed, because nothing here dispatches.

## Known gaps
- Compiled against MAX 8.6.4 in FlowIoC-local-test on 2026-09-17 (the SDK from AppLovin's registry,
  EDM4U 1.2.182 from openupm); the Editor stub took the whole path - initialize, both loads, a
  rewarded show, Grant Reward, close, `Rewarded`, the reload - with placeholder ad unit ids. Not
  yet run on a phone against live ad units.
- No `SetUserId` for MAX's reward validation postbacks.
- The ATT prompt on iOS is not asked here; MAX's own consent flow, enabled in the Integration
  Manager, or a consent module asks it before `Initialize`.
