# ResourceFlySampleScreen

## Purpose
The sample screen of ResourceFly's test module: three counters, one per ready-made motion, each with a source and a Fly button.

## Concepts
resource fly sample, sample screen, motion, scatter, direct, curved, Pool_ResourceFlySample

## Decisions
- **Editor-only.** Every script is under `#if UNITY_EDITOR`, the screen loads from Resources, and
  its prefab, the icon prefab and the pool group sit under the module's `Editor/` folder, so
  nothing of it reaches a player build or an Addressables group. It exists for the test module's
  scene.
- **Listed on `ResourceFlyTestRoot` only.** The sample is not a feature of the ResourceFly
  service, so its context is not on `ResourceFlyServiceRoot`, which ships.
- **A press runs the order a game binds.** Each lane's Fly signal is bound to
  `IResourceFlyService.Commands.Reserve`, then `SaveSampleGrantCommand` - the save a game's grant
  would make - then `IResourceFlyService.Commands.Fly`, so the counter holds still until the icons
  land. The saved values live in `ResourceFlySampleModel`, in place of a game's profile.
- **The opening Command fills it.** The test module's `OpenSampleScreenCommand` registers the three
  counters and sources from the view `Show` returns, the way a game's opening Command fills a
  screen; the Mediator only passes presses on.
- **Each counter names its motion.** The three `ResourceFlyCounterDisplay`s carry the Scatter,
  Direct and Curved assets in their Motion slot, which is the per-counter choice a game makes.
- **The icons are pooled.** `Pool_ResourceFlySample` lists `PB_ResourceFlySampleIcon` under
  `ResourceFlySampleIcon`, and the scene files it through a `PoolSubContext` entry on
  `ResourceFlyTestRoot`.
